## 認証APIのRedisレート制限

- **使用箇所**：`backend/internal/middleware/auth_rate_limit.go`、`auth_rate_limit_test.go`、`backend/cmd/api/main.go`、`api/openapi/openapi.yaml`
- **AIの利用内容**：IPと認証APIの組み合わせで60秒固定ウィンドウの呼び出しを計数し、上限超過時に429とRetry-Afterを返すGo/Echoミドルウェアを作成。Luaにより初回TTLとINCRを原子的に処理。Redis障害時は503で失敗させる。
- **採用理由**：パスキーの登録・ログインで必要となるRedisアクセスや署名検証などを悪用した過負荷・DoSの被害を軽減するため。WAFの集計とは異なる厳格な回数上限を実装する。
- **開発者による対応**：最終コードレビュー、ローカルおよびAWS動作検証、採用判断は未実施。
- **検証方法**：ローカルPostgreSQL・Redisを接続して`go test ./... -coverprofile=... -count=1`を実行。認証APIの境界条件と実RedisでのLuaスクリプトによる11回目の429・TTLを確認した。`authRateLimit`のカバレッジは83.3%、middlewareパッケージは93.8%、全パッケージは65.9%。
- **代表的なプロンプト**：「INCRとは」「これどこで10回の制限指定してるの？なんで60秒後なの？」

## AWS WAFによるHTTP flood緩和

- **使用箇所**：`infra/modules/waf/main.tf`、`infra/aws.tf`、`infra/modules/alb/outputs.tf`
- **AIの利用内容**：AWS WAF v2のREGIONAL Web ACLとALB関連付け、認証パスに絞ったIP単位のレートベースルールをTerraformで追加。
- **採用理由**：Shield StandardによるL3/L4の基盤保護だけでは認証APIへのL7 HTTP floodを細かく制限できないため。Goへ到達するリクエストの抑制を狙う。
- **開発者による対応**：AWS WAFの継続料金と誤検知の許容度の確認、`terraform plan`のレビュー、適用は未実施。
- **検証方法**：`terraform fmt -check -recursive`と、一時作業ディレクトリでの`terraform init -backend=false`・`terraform validate`に成功。AWSでのWAF動作検証と`terraform apply`は未実施。
- **代表的なプロンプト**：「WAFで対策するのはDoS？インジェクション、CSFR？」「Shieldで防いでいてもWAFはあった方がいいの？」「大量のHTTPSリクエストは大量のTCP接続数って認識されないの？」
