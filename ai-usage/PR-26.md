# AI利用記録：PR #26

PR：[feat: add GitHub Actions CI/CD with AWS OIDC](https://github.com/catechlounge/kyoya67-todo/pull/26)

## 利用モデル・ツール

- ツール：OpenAI Codex
- 利用目的：GitHub ActionsとAWS OIDCの認証基盤をTerraformで実装する
- 最終的な要件解釈、権限範囲、コード確認、検証は開発者が行う

## GitHub Actions用OIDCとIAMロール

- 使用箇所：`infra/modules/iam/`、`infra/aws.tf`、`DESIGN.md`
- AIの利用内容：GitHub ActionsがAWSへ短期認証でアクセスするため、IAM OIDCプロバイダー、GitHub Actions用IAMロール、信頼ポリシー、ECR・ECS・PassRole権限を既存IAMモジュールへ追加した
- 採用理由：長期AWSアクセスキーをGitHubへ保存せず、対象リポジトリの`main`ブランチから発行されたGitHub Actionsトークンだけを許可するため
- 開発者による対応：AWSサービス単位の構成方針に合わせ、OIDCプロバイダーとGitHub Actions用ロールを`infra/modules/iam/`へ集約した。信頼対象を`catechlounge/kyoya67-todo`の`main`ブランチに限定した
- 検証方法：`terraform fmt -recursive`、`terraform validate`、`git diff --check`を実行した。GitHub Actionsの実行およびAWS上でのOIDC引き受け確認は未実施
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「GitHub ActionsからAWSへOIDCで認証するためのOIDCプロバイダーとIAMロールをTerraformで管理したい。既存のIAMモジュールへ集約し、対象リポジトリとmainブランチに信頼範囲を限定したうえで、ECR pushとECSデプロイに必要な最小限の権限を設計して」

## mainマージ時のCD

- 使用箇所：`.github/workflows/cd.yml`、`infra/modules/iam/`、`DESIGN.md`
- AIの利用内容：`main`へのpushをトリガーに、OIDC認証、ECRイメージpush、ECSタスク定義更新、ECSサービスデプロイを行うworkflowを整理した
- 採用理由：リリースブランチである`main`へのマージ後だけAWS環境へ自動デプロイし、IAM信頼ポリシーの対象も`main`に限定するため
- 開発者による対応：環境依存値はGitHub Variablesから注入し、workflowへ固定値を埋め込まない構成にした
- 検証方法：workflowファイルの差分確認とTerraformの`validate`を実行した。GitHub Actionsの実行、ECR push、ECS更新は未実施
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「GitHub ActionsのCDはmainへのマージ後だけ実行したい。OIDC信頼ポリシーの対象ブランチとworkflowのトリガーをmainに限定し、ECRからECSへデプロイする構成にして」

## Pull Request時のCI

- 使用箇所：`.github/workflows/ci.yml`、`DESIGN.md`
- AIの利用内容：Pull Requestを`develop`または`main`へ向けて作成・更新した際に、Goのテストとvet、sqlcの検証・生成差分確認、Terraformのformat・validate、Dockerイメージのビルドを実行するCIを整理した
- 採用理由：AWSへの認証・デプロイを行うCDと分離し、マージ前にコード・SQL・Terraform・コンテナビルドの問題を検出するため
- 開発者による対応：CIでは秘密情報やAWS認証を使用せず、既存のディレクトリ構成とTerraformのバージョンに合わせた。CIの実行結果は未確認
- 検証方法：workflowの差分と`git diff --check`を確認した。GitHub Actions上での実行は未実施
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「Pull Request時にGo test・go vet・sqlc vet/generate・Terraform fmt/validate・Docker buildを実行するCIを追加したい。AWS認証やデプロイはCDと分離し、developとmain向けPRを対象にするworkflowを設計して」
