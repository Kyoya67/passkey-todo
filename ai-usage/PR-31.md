# AI利用記録：PR #31

## 利用モデル・ツール

- ツール：OpenAI Codex
- 利用目的：ECS Serviceの起動・停止運用と、Terraform・CD間のタスク定義管理の整理
- 最終的な要件解釈、AWS操作の実行判断、コード確認、検証は開発者が行う

## ECS Serviceの起動・停止運用

- 使用箇所：`Makefile`、`README.md`
- AIの利用内容：ECS Serviceのdesired countを`0`または`1`へ変更するAWS CLIコマンドをMakefileに追加し、状態確認コマンドとREADMEの運用手順を整理した
- 採用理由：利用時だけバックエンドタスクを起動し、利用しない時間帯は停止することで、ECSタスクの稼働時間を管理するため
- 開発者による対応：起動・停止はAWSリソースと料金に影響するため実行せず、`make -n`によるコマンド展開確認と、読み取り専用の`ecs-status`だけを実行した
- 検証方法：`make -n ecs-start ecs-stop ecs-status`を実行し、AWS CLIコマンドの展開を確認した。`AWS_PROFILE=ca-techlounge-todo-terraform make ecs-status`でdesired count、running count、pending count、Service statusを確認した
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「Issue #9のECS Serviceを必要時のみ起動・停止する運用を実装する。desired countを0/1で変更する方法、コスト面の注意、READMEに記載する起動・停止手順を整理して」

## TerraformとCDによるタスク定義管理

- 使用箇所：`infra/aws.tf`、`infra/modules/ecs/variables.tf`
- AIの利用内容：Terraformで作成したECS Serviceが、CDで登録された新しいタスク定義リビジョンや手動変更したdesired countを旧状態へ戻さないよう、`lifecycle.ignore_changes`を追加し、未使用の変数を削除した
- 採用理由：Terraformは基盤リソース、CDはデプロイ時のタスク定義リビジョンを管理する責務分担に合わせるため
- 開発者による対応：Terraform planの差分を確認し、無視する対象をServiceの`desired_count`と`task_definition`に限定した。タグや他のService設定は無視対象にしていない
- 検証方法：`terraform fmt -check -recursive`と`git diff --check`を実行した。`terraform validate`はAWSプロバイダプラグインの読み込みエラーにより完了していない
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「CD成功後にECS Serviceのtask definitionが旧リビジョンへ戻るTerraform差分が出ている。lifecycle.ignore_changesを利用し、task_definitionとdesired countを無視するように修正して」
