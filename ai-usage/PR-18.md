## TODO REST APIの実装

- 使用箇所：`backend/internal/handler/todo.go`、`backend/internal/service/todo.go`、`backend/internal/repository/todo.go`、`backend/internal/router/router.go`
- AIの利用内容：Handler、Service、Repositoryの責務分離、依存性逆転のためのインターフェース、4つのREST APIの実装方針を相談した
- 採用理由：HTTP処理、業務ルール、DBアクセスを分離し、後続のテストでFakeへ差し替えられる構成にするため
- 開発者による対応：課題文と既存設計を確認し、実装内容を理解したうえで修正・採用した
- 検証方法：`go test ./...`、`go vet ./...`、手動HTTPリクエストで確認した
- 代表的なプロンプト：
  - 「Issue #2の必須REST API 4本を実装して」
  - 「Handlerで初期化するServiceをインターフェースにして疎結合にして」

## sqlc・PostgreSQLエラー処理

- 使用箇所：`backend/db/query/todos.sql`、`backend/internal/database/sqlc`、`backend/internal/repository/todo.go`、`backend/internal/service/todo.go`
- AIの利用内容：`pgx.ErrNoRows`、DELETEの`RETURNING`、sqlcの引数命名、`pgtype.Text`の意味を確認した
- 採用理由：存在しないTODOをアプリケーション側で404へ変換し、生成コードの引数名を読みやすくするため
- 開発者による対応：SQLを修正してsqlc生成コードを更新し、生成結果を確認した
- 検証方法：`sqlc generate`、`sqlc vet`、存在しないIDへの更新・削除リクエストを確認した
- 代表的なプロンプト：
  - 「PostgreSQLはデータが見つからない時エラーを返すか公式情報で確認して」
  - 「Column1をTitleへ変更して」

## Swagger UI・CORS

- 使用箇所：`compose.yaml`、`.env.example`、`backend/internal/config/config.go`、`backend/internal/middleware/cors.go`、`backend/cmd/api/main.go`
- AIの利用内容：ローカルSwagger UIの起動方法、API環境の切り替え、Swagger UIとバックエンド間のCORS、クラウド配置方針を相談した
