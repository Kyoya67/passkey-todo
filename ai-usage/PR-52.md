## faviconとテキスト選択の調整

- 使用箇所：`frontend/favicon.png`、`frontend/index.html`、`frontend/style.css`
- AIの利用内容：提供されたアイコン画像を基にfavicon用画像の余白を調整し、PNGとして配置した。HTMLからfaviconを参照し、通常の画面テキストは選択できないようにしつつ、入力欄では選択・編集を維持した
- 採用理由：ブラウザのタブでもアプリを識別できるようにし、カードのドラッグ中にテキストが選択される操作上の違和感を減らすため
- 開発者による対応：画像を指定し、develop起点のブランチで作業するよう依頼した。その後、開発者がfavicon画像を差し替えてコミットしたため、PRに含まれる最終画像はAIが最初に保存した画像とは異なる
- 検証方法：`cd frontend && npm test`で26テスト成功、`npm run format:check`成功、faviconファイルの配置を確認した。実ブラウザでの表示・選択操作は未確認
- 代表的なプロンプト：「まずfaviconの設定。そしてこのアプリではこの画像みたいにテキスト選択できないようにしたい。faviconで使う画像は今はった二枚目の画像にして。ブランチをdevelopから作って」

## direnvによるAWS設定の一元化

- 使用箇所：`.envrc`、`.gitignore`、`infra/.envrc`、`Makefile`
- AIの利用内容：共通のリージョン・ECS名をルートの`.envrc`へ移し、`infra/.envrc`から参照するようにした。個人のAWSプロファイルはGit管理しない`.envrc.local`へ分離し、Makefileの個人用デフォルト値を削除して必要な環境変数の確認を追加した
- 採用理由：個人のプロファイル名を共有設定へ埋め込まず、ルートと`infra/`で同じ設定を重複なく使うため
- 開発者による対応：Makefileのハードコードを見直すよう提案し、direnvへの集約を指定した。後続の開発者コミットで手動マイグレーション用`db-migrate-ecs`コマンドがMakefileから削除された。この削除はAIによる変更ではない
- 検証方法：ルートと`infra/`の両方で`direnv exec`を使い、同じAWS設定が読み込まれることを確認した。`make -n ecs-status`でコマンド展開を確認し、`git diff --check develop...HEAD`を実行した。AWS操作は未実施
- 代表的なプロンプト：「この辺ハードコードよくないか？.envからにしたほうが」「じゃあdirenvに書こう。でもinfraにも.envrcあるから二回書くみたいで嫌だ」
