# AI利用記録：PR #39

PR：[feat: enable HTTPS for backend API](https://github.com/catechlounge/kyoya67-todo/pull/39)

## 利用モデル・ツール

- ツール：OpenAI Codex、Terraform、AWS ACM、ALB、Route 53、curl
- 利用目的：APIをHTTPSで公開するためのACM証明書とALB設定
- 最終的な要件解釈、AWS操作の実行判断、コード確認、検証は開発者が行う

## APIのHTTPS公開

- 使用箇所：`infra/modules/acm/`、`infra/modules/alb/`、`infra/modules/security_groups/`、`infra/aws.tf`、`DESIGN.md`
- AIの利用内容：HTTPS接続不可の原因を、ACM証明書、ALBリスナー、Security Group、RDS接続用CAの責務に分けて整理した
- 採用理由：APIクライアントからHTTPSで接続できるALB構成をTerraformで再現するため
- 開発者による対応：ACMのDNS検証、ALBの443番HTTPSリスナー、80番から443番へのリダイレクト、443番のSecurity Group許可を追加した。RDS接続用CAはAPI公開用証明書とは分離した
- 検証方法：Terraformのformat、`git diff --check`、ACM・ALB設定、`curl`によるHTTPS接続を確認した
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「APIのHTTPS接続ができない。ACM証明書、ALBのHTTPSリスナー、HTTPリダイレクト、RDS接続用CA証明書の役割を整理してTerraformへ反映して」
