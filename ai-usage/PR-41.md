# AI利用記録：PR #41

## 利用モデル・ツール

- ツール：OpenAI Codex、AWS CLI、Docker Buildx、ECR、ECS
- 利用目的：マイグレーション用コンテナイメージをコミットハッシュで管理し、ECSで実行できる状態にする
- 最終的な要件解釈、AWS操作の実行判断、コード確認、検証は開発者が行う

## マイグレーションイメージのタグ管理

- 使用箇所：`.github/workflows/cd.yml`、`README.md`、`DESIGN.md`
- AIの利用内容：バックエンドと同様に、マイグレーション用イメージも`latest`ではなくGitHub ActionsのコミットハッシュでECRへpushし、そのタグをECSタスク定義へ反映して実行する構成を検討した
- 採用理由：`latest`の上書きによる実行対象の不明確さを避け、どのコミットのマイグレーションを適用したか追跡できるようにするため
- 開発者による対応：CDでコミットハッシュをタグにしたイメージをpushし、ECSタスク定義のイメージを差し替えてからワンショットタスクを実行する構成を採用した
- 検証方法：ECRのイメージタグ、マニフェスト、ECSタスク定義をAWS CLIで確認した。GitHub ActionsのYAML構文と`git diff --check`を確認した
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「バックエンドはコミットハッシュをイメージタグにしている。マイグレーション用イメージも同じ方式に変更し、CDでタグを手動指定せず、pushしたタグをECSタスク定義へ反映して実行する構成にして」

## ECSでのプラットフォーム不一致

- 使用箇所：マイグレーション用ECRイメージ、`backend/Dockerfile.migration`
- AIの利用内容：ECSから`image Manifest does not contain descriptor matching platform 'linux/amd64'`が発生したため、ECSの実行プラットフォームとMacでbuildしたイメージのアーキテクチャを比較した
- 採用理由：Apple SiliconのMacでbuildしたイメージは`linux/arm64`になり得る一方、ECSタスクは`linux/amd64`で実行されるため、ECRへAMD64向けイメージを登録する必要がある
- 開発者による対応：`docker buildx build --platform linux/amd64 --push`を使用して、マイグレーションイメージをbuild・pushした。バックエンドがGitHub Actions上で正常に動作していることから、ローカルMacでの手動pushとCD上のbuild環境を分けて原因を推測し、ECRマニフェストをAWS CLIで確認した
- 検証方法：ECRマニフェストに`linux/amd64`が含まれることを確認し、マイグレーションタスクとクラウド上のフロントエンドが正常に動作することを開発者が確認した
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「ECSのAPIコンテナは起動しているが、Macからpushしたマイグレーションイメージだけ`linux/amd64`のマニフェストがない。ECRのマニフェストとECSタスク定義を確認して、原因と再push方法を特定して」

## ECRのimmutableタグによる再push失敗

- 使用箇所：ECRの`kyoya67-todo/migration`リポジトリ、初回イメージpush手順
- AIの利用内容：AMD64版を同じタグへ再pushした際に、ECRから`The image tag 'latest' already exists ... cannot be overwritten because the tag is immutable`が返ったため、CPUアーキテクチャ問題とタグ上書き拒否を分離して分析した
- 採用理由：既存のARM64タグをそのまま上書きできないことを確認し、対象タグを削除してからAMD64版をpushする必要があると判断した
- 開発者による対応：ECRコンソールで既存の誤った`latest`タグとコミットタグを確認・削除し、AMD64指定のBuildxコマンドで再pushした
- 検証方法：ECRのマニフェストを再確認し、マイグレーションタスクが成功し、クラウド上のフロントエンドからAPIを操作できることを確認した
- 代表的なプロンプト（実際の相談内容を要約）：
  - 「AMD64を指定して再buildしたが、ECRのタグがimmutableで上書きできない。エラーの意味、既存タグの扱い、削除後に再pushする安全な手順を整理して」
